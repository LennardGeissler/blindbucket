# Browser uploads through blindbucket

A common pattern for web applications: the backend holds the S3 credential, and
when a user picks a file, it hands the browser a presigned URL to upload that one
file to. The bytes go from the browser to storage without passing through the
backend. With blindbucket in between, they go from the browser to the gateway,
which encrypts them on the way through, and the provider holds ciphertext.

**Measured:**
- **In CI, by the integration tests:** a headless Chrome on a page from another
  origin uploads by presigned URL and reads the ETag back, and a page on an
  unlisted origin is refused. Every way the holder of a URL could try to do more
  than it was signed for is refused (`internal/proxy/integration/`).
- **Once, on 2026-10-20:** URLs generated by the AWS SDK for JavaScript v3.1152.0
  and boto3 1.43.114, against a gateway in front of MinIO. That is the table below.

The design is [ADR-036](../adr/ADR-036-presigned-uploads.md).

## What works

| Step | What it shows |
|---|---|
| A URL from JavaScript v3 with `requestChecksumCalculation: "WHEN_REQUIRED"`, or from boto3 | the upload is stored, and reads back identical |
| A URL that binds `ContentLength` | a body of another length is refused, `403 SignatureDoesNotMatch` |
| A URL that binds `ChecksumSHA256`, in the query (JavaScript) or as a header (boto3) | that body is stored; any other is refused, `400 BadDigest`, and nothing is stored |
| A URL that binds `Metadata` and `ContentType` | stored and read back. With boto3 the browser has to send the signed headers, or gets `403` |
| A URL that binds `IfNoneMatch: "*"` | the first upload is stored, the second is refused, `412` |
| A multipart upload: the backend creates and completes it, the browser uploads each part by URL | the object reads back as its parts |
| A body over `max_size` | refused before it is read, `400 EntityTooLarge` |
| A presigned download from either SDK | served |

At the provider every object is ciphertext.

Not measured: Uppy or any other upload library, a CDN in front of the gateway,
and providers other than MinIO for the browser path.

## The gateway

```yaml
server:
  listen: "0.0.0.0:9000"      # reachable by the browsers, with TLS
  tls:
    cert_file: /etc/blindbucket/tls.crt
    key_file: /etc/blindbucket/tls.key
  presign:
    uploads:
      max_size: 100MiB        # unset: presigned uploads are refused
      max_expiry: 15m         # the default is 1h
  cors:
    allowed_origins: ["https://app.example"]
```

- **`presign.uploads.max_size`** switches uploads on. It is the most one request
  may carry, so for a multipart upload the most one part may carry, up to
  `5GiB`. The total of a multipart upload is the backend's to bound, since the
  backend creates it, signs each part and completes it.
- **`presign.uploads.max_expiry`** caps how long an upload URL may be valid. An
  upload URL can be used again until it expires, so keep it short.
- **`cors.allowed_origins`** lists the pages that upload, exactly as a browser
  sends `Origin`: scheme and host, a port only if it is not the default, no
  trailing slash. There is no wildcard. The gateway answers the browser's
  preflight itself. The bucket's own CORS configuration at the provider plays no
  part, because the browser never talks to the provider.
- **TLS.** The body of a presigned upload is not covered by the signature, so
  between browser and gateway TLS is what protects it.

The gateway has to be reachable by the browsers. A presigned URL names the
gateway, not the provider, which holds ciphertext under a name the browser
cannot read.

## The backend

The backend presigns as it would against S3, with the gateway as the endpoint
and a client credential from the gateway's `clients`.

**JavaScript v3.** Set `requestChecksumCalculation: "WHEN_REQUIRED"`. With its
default, the SDK binds the CRC32 of an *empty* body, `AAAAAA==`, into every URL,
and the gateway verifies it as it verifies every checksum: such a URL takes only
an empty upload, and any real file gets `400 BadDigest`.

```js
import { S3Client, PutObjectCommand } from "@aws-sdk/client-s3";
import { getSignedUrl } from "@aws-sdk/s3-request-presigner";

const s3 = new S3Client({
  endpoint: "https://blindbucket.example",
  region: "us-east-1",
  forcePathStyle: true,
  requestChecksumCalculation: "WHEN_REQUIRED",
});

const url = await getSignedUrl(s3, new PutObjectCommand({
  Bucket: "uploads",
  Key: `users/${userId}/${fileId}`,
  ContentLength: file.size,   // binds the size the browser announced
  IfNoneMatch: "*",           // makes the URL single-use
}), { expiresIn: 900 });
```

**boto3.** Build the client with `signature_version="s3v4"`, because botocore
presigns with SigV2 against a custom endpoint unless told otherwise, and this
gateway verifies SigV4 only. boto3 signs every parameter as a header, so the
browser has to send each one:

```python
s3 = boto3.client("s3", endpoint_url="https://blindbucket.example",
                  config=Config(signature_version="s3v4", s3={"addressing_style": "path"}))
url = s3.generate_presigned_url("put_object", ExpiresIn=900, Params={
    "Bucket": "uploads", "Key": key, "ContentType": "image/png",
})
# The browser must then send Content-Type: image/png.
```

What the backend can bind, and what it buys:

- **`ContentLength`**: the browser cannot upload a different size.
- **A checksum** (`ChecksumSHA256`, `ContentMD5`): the browser can upload that
  one content and nothing else. Useful when the backend knows the file in
  advance, which for a user's upload it usually does not.
- **`IfNoneMatch: "*"`**: the URL creates the object once, and a second use gets
  `412`. Without it, a URL overwrites its key every time it is used until it
  expires. This holds where the provider enforces the condition; Garage v2.4.1
  does not ([COMPATIBILITY.md](../COMPATIBILITY.md#a-clients-own-conditional-writes)).
- **Metadata**: stored with the object. A browser cannot add metadata of its own:
  an `x-amz-*` header the URL did not sign is refused with `403`.

## The browser

```js
const response = await fetch(url, {
  method: "PUT",
  body: file,
  headers: { "If-None-Match": "*" },   // every header the URL signed
});
if (!response.ok) throw new Error(await response.text());
const etag = response.headers.get("ETag");
```

For a multipart upload, the backend calls `CreateMultipartUpload` and
`CompleteMultipartUpload` with its own credential, and presigns one
`UploadPart` URL per part. The browser uploads each part and hands the `ETag`s
back to the backend. Keep them exactly as they come: the gateway's part ETags are
longer than S3's, because each carries the part's salt to the completion
([ADR-014](../adr/ADR-014-part-salts-in-the-manifest.md)). Every part but the
last must be a multiple of the gateway's chunk size, 64 KiB unless
`crypto.log2_chunk_size` says otherwise; S3's 5 MiB minimum already is one.

Creating, completing and aborting an upload, deleting, copying and every bucket
operation are refused by URL. They are the backend's to do.

## Troubleshooting

- **`400 BadDigest` for every upload from JavaScript**: the SDK's default bound
  the checksum of an empty body. Set `requestChecksumCalculation: "WHEN_REQUIRED"`.
- **`403 AccessDenied`, "presigned uploads are not served here"**:
  `presign.uploads.max_size` is not set.
- **`403 SignatureDoesNotMatch`**: the browser did not send a header the URL
  signed (with boto3, every parameter is one), or sent a body of another length
  than a signed `ContentLength`.
- **`403 AccessDenied`, "is not among the headers this presigned URL signed"**:
  the browser sent an `x-amz-*` header the backend did not sign.
- **`403 AccessDenied` on an upload URL that works for a download**: the URL is
  valid for longer than `presign.uploads.max_expiry`. The gateway's log says so.
- **The browser reports a CORS error**: the page's origin is not in
  `cors.allowed_origins` exactly as the browser sends it (compare with the
  `Origin` header in the browser's network tab), or the page sends a header
  outside the set the preflight allows (`authorization`, for instance, or
  `x-amz-acl`). The gateway logs every refused preflight with the origin.
- **`400 EntityTooLarge`**: the body is over `max_size`. For a larger file,
  upload in parts.
